## 项目一:跨越速运多端小程序(下单/查件核心业务)

**角色:** 核心开发 | **技术栈:** Taro 4 + Vue 3 + TS + Pinia + Webpack 5 | 周迭代发布 49+ 版本(8.2.x)

**背景:** 官方小程序,承载下单、查件、支付等核心物流业务;一套代码运行微信/支付宝/高德/H5 及三端 App 容器,且下单/查件为独立仓库,存在多团队并行与包体积双重约束。

**核心工作:**

1. **多仓库子应用架构:** 3 个业务子应用 git 独立仓库演进,自研编排插件 dev 按本地拼装、prod 按分支拉取、chokidar 热同步,多团队并行迭代互不阻塞。
2. **自研 Taro 构建插件:** 分包异步化插件(Babel 改写 webpack runtime 实现小程序 `require.async` + chunk hash 分桶回写 app.json)、动态分包 import 插件、按需调试页插件(依赖扫描裁剪,fail-fast)。
3. **7 端运行时抹平:** 条件编译 + 平台文件替换 + 构建后模板改写;落地 4 套支付链路、多端登录(授权码队列防并发),7 组 APM Key 按端隔离。
4. **性能体系:** 分包异步化 + `lazyCodeLoading` 按需注入 + tabBar 分包预下载 + 主包瘦身(CSS 短类名/Terser-SWC)+ 骨架屏 90+ 处/分帧渲染 + lz-string 缓存压缩;建立总包 30MB / 子包 2MB 构建期体积门禁。
5. **业务难点:** Schema 驱动服务端配置化下单页;自托管 mapbox 轨迹(点碰撞标注、增量轮询自愈、小车动画);扫码转月结财务级业务(三级权限校验);md5 双签请求层 + 灰度头 + 子包拦截器;WebSocket 长连接。
6. **监控与规范:** 私有化 APM + 曝光指令 + 首屏耗时打点 + 内存告警;推行 OpenSpec 规格驱动(39 业务 spec,禅道联动)与 AI 辅助审查流程。

**成果:** 7 端一套代码稳定周迭代 49+ 版本;子应用独立发布、体积门禁内建 CI;kycli 一条命令六端构建上传(双 CI SDK + Android/iOS 签名物料)。

## 项目二:跨端小程序组件库 kye-miniui

**角色:** 核心建设 | **技术栈:** Vue 3 + Taro 4 + Vite + pnpm monorepo + VitePress | 被主工程强制依赖,累计发布 440+ 版本

**背景:** 多端业务缺乏统一 UI 基建,原生表单组件在微信/支付宝/H5 表现不一,需建设跨端组件库统一视觉交互并配套文档、脚手架与发布链路。

**核心工作:**

1. **46 个跨端组件:** 含自研滚轮级联选择器(touch 手势 + 惯性滚动)、虚拟列表、Canvas 2.0 图片裁剪、日历与手势组件族。
2. **三端差异五层抹平:** 条件编译动态加载端别实现、文件级多端(`*.wx/alipay/h5.vue`)、平台 Hooks、端别样式、API canIUse 守卫。
3. **工程产物:** Vite lib 输出 ES+UMD+DTS+CSS 四格式;61 文件 SCSS 基建(BEM mixin 33 个 + 主题变量);独立 Taro 原生组件注册插件包。
4. **CLI 与文档站:** 一键建组件五步流水线(锚点插桩自动注册入口)+ vue-docgen-api 自动 API 文档;VitePress「文档/演示一套代码」(50 文档 + 47 demo,iframe 真机预览,线上 miniui-doc 站点)。
5. **发布链:** commitlint → 自动版本/CHANGELOG(hash 去重)→ Nexus 私服 + verdaccio 验证 → CI/CD;每组件配套 SKILL.md 供 AI 辅助开发。

**成果:** 三端统一、业务侧禁用原生表单组件;组件「创建+文档+发布」收敛为两条命令,新组件接入从小时级降至分钟级。

## 项目四:PC 管理后台门户(微前端基座)

**角色:** 核心开发 | **技术栈:** Vue 3 + TS + Webpack 5 + Pinia 3 + micro-app + 自研微模块/通信层 + 自研组件库 | 500+ 源文件

**背景:** PC 管理端门户,作为微前端基座同时承载原生页面、iframe 老轻应用与微前端子应用;需不停机承接存量 iframe 生态,并完成 Vuex→Pinia、Element Plus→自研组件库两轮迁移。

**核心工作:**

1. **微前端基座架构:** 「原生 / 自研微模块 / micro-app / iframe」四形态承载并存——自研微模块为主推、micro-app(pure 路由模式)作存量兼容、15 组 iframe 路由渐进迁移;子应用 entry 由菜单接口按 menuCode 动态下发,配置化接入。
2. **自研微模块框架:** fetch manifest 解析入口 → ProxySandbox 沙箱执行 → vue-router 动态注入 + 原始路径回放(防 404 吞路由)→ activate/mount 生命周期;共享运行时下制定插件红线(禁装 Pinia、store id 命名空间),根治 `activePinia` 覆盖导致 store 串实例。
3. **跨应用通信层(micro-native):** 能力注册中心 + RPC/事件总线——基座注册 6 个能力域,调用按运行模式自动路由通道(iframe=postMessage、micro-app=官方通道、微模块=沙箱直连、独立=本地直执),子应用零改动跨形态运行;`__call` 统一 6 种客户端壳通信(全局函数/mbQuery/CefSharp/WebView2/Electron/跨声 3.0),跨声异步回调映射 Promise 化,50+ 壳能力按域扩展。
4. **零停机迁移:** storeBridge 以旧 Vuex dispatch/commit 同构接口承接 iframe 子应用调用并映射 Pinia,存量零回滚;8+10 个 store 全量迁 Pinia;自研 LocalStorageManager 登录身份动态键缓存(防多账号越权)+ stale-while-revalidate 秒显。
5. **登录鉴权重构:** 统一登录外置 + token URL 免登;8 步守卫管道(按需阻塞 + 3s 超时降级、动态权限码防手输绕过),登录切换竞态以 6 组 Jest 单测固化。
6. **性能与工程:** CDN externals 共享运行时 + 白屏检测 + 首屏骨架屏;requestIdleCallback 空闲预加载多页签保活;20 个模块注册表配置化首页;自研组件库主题工程补丁(EP 样式加载顺序/barrel 导出/peer 依赖)。

**成果:** 「iframe 子应用 → 微前端基座」演进零回滚;新子应用按检查清单接入即复用运行时/主题/权限/请求层与 Native 能力;两轮基建迁移业务无感完成。

## 附录:口径与面试提示

- **表述边界:** ①小程序 i18n 目录非国际化项目,勿写;②组件库无单测,写「3 端预览验证 + vue-tsc」;③PC 后台 README「Pinia+Vuex 并存」已滞后,实际无 vuex,以 storeBridge 口径为准;kyeIframeBridge 旧提法过期,现行 `src/utils/iframeBridge`(Postmate TS 版)。
- **高频追问预案:** ①分包异步化 → splitChunks 改写 → hash 分桶 → Babel 改写 runtime → 回写 app.json;②多端差异 → 五层抹平,举胶囊按钮/输入法案例;③为什么自研微模块而非全用 qiankun → 存量 iframe 生态 + 注入式共享运行时,子应用无独立框架开销;④store 串实例 → activePinia 被子应用覆盖,禁装 Pinia + 显式传基座实例 + id 命名空间;⑤子应用怎么调壳能力 → micro-native 注册中心按运行模式路由通道,跨声回调映射 Promise 化。
- **可补充方向:** 目标岗位偏 AI 工程时,强调 OpenSpec 规格驱动、SKILL.md 组件知识库、AGENTS.md AI 审查流程,与 Agent 项目经验形成「前端工程 + AI 工程」复合画像。
