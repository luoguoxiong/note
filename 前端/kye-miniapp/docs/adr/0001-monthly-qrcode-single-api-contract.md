# 扫码转月结页：单接口契约 + 接口返回有效期

需求 #570652「扫码转月结」页面的月结码状态只调用一个后端接口 `web.user.fmsSettlement.getQRCode`（无入参），页面状态由其 `data.status` 枚举驱动（0 成功 / 2 客户状态异常 / 3 非月结 / 4 无权限 / 5 二维码获取失败），异常文案直接展示后端返回的 `statusDesc`；二维码有效期展示与到期自动刷新均以接口返回的 `generationDate` / `expirationDate`（毫秒时间戳）为准，展示用 `@/public/utils` 的 `formatTime` 精确到分钟，到期按 `expirationDate - 当前时刻` 的剩余时间武装定时器重新生成。

**内部员工判定不在该接口契约内**：是否内部员工由前端进入页面时单独调用 `web.customer.isEmployee`（入参当前登录手机号）判断，命中则整页缺省拦截、不再调用 `getQRCode`；身份校验每次进入页面只做一次，放行后的定时刷新不再重复调用。

这与 PRD 的描述不同：PRD 设计是"权限校验接口 + 财务生成码接口"两段式调用。后端最终落地的契约把客户状态、月结方式、转月结权限的优先级判定与异常文案（含脱敏主授权号）收敛到单接口，仅内部员工判定由前端调公共接口完成。

## Consequences

- 前端不存在"校验通过但生成失败"的中间态组合，状态机只有：加载中 / 正常 / 内部员工（isEmployee 拦截） / 异常（statusDesc + 按 status 决定按钮）。
- 有效期计时依赖服务端下发的毫秒时间戳，前端不做本地推算；`expirationDate` 缺失时按已过期处理（回到页面立即重新生成、不武装定时器）。
