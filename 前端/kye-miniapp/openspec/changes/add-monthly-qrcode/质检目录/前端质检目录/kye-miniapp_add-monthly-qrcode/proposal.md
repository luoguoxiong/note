# 扫码转月结（月结二维码）

## Why

末端到付运单派送时，客户要求转月结只能依赖司机口头确认 + 销售人工转单，存在效率低、沟通成本高的问题；当客户后台已被回收/报废/拉黑时，转单失败且运费无法收回，形成资损。本次在互联网端（微信小程序、支付宝小程序、APP 等多端）新增月结二维码能力：月结客户出示月结码，司机用取派端扫码即完成转月结确认，扫码时实时校验结算资格，消除「口头确认 → 人工转单」中间环节。

禅道需求链接：https://zentao.ky-tech.com.cn/platform-home/#/need-detail/570652

- 「我的页面 → 客户支持」区域新增「扫码转月结」入口：入口显示（结算方式=月结、后台状态=正常、已开通转月结权限 3 条条件及定时刷新）由轻应用后台配置实现，本次无前端代码变更。

- 新增月结二维码页面：进入页面先调 `web.customer.isEmployee` 拦截内部员工（整页缺省，每次进入只校验一次）；其余状态调用单接口 `web.user.fmsSettlement.getQRCode`，由返回 `data.status` 枚举（0 成功 / 2 客户状态异常 / 3 非月结 / 4 无权限 / 5 二维码获取失败）驱动，前端不做权限判断。
- 二维码有效期由前端以「接口调用发起时刻 + 10 分钟」本地计时并展示；到期自动重新调用接口生成新码，用户也可点击刷新按钮手动重新生成。
- 异常场景按后端返回状态展示对应文案（异常文案直接使用后端 `statusDesc`）：非月结提示、客户后台状态异常提示（附「联系商务」按钮）、无转月结权限提示（含脱敏主授权号手机号）、二维码获取失败提示（附重新加载）；内部员工为整页缺省提示。
- 本次不含取派端扫码端改造，不含月结账号开通/权限配置流程（主授权号在客户后台配置）。

## Capabilities
### New Capabilities

- `monthly-qrcode-page`：月结二维码页面的单接口状态机（加载中/正常/内部员工/各类异常）、二维码展示与有效期本地计时、到期自动刷新与手动刷新、异常文案展示与联系商务/重新加载交互。

### Modified Capabilities

无。本次为新增独立页面，入口由后台配置下发，不改变既有菜单结构与既有页面行为。
