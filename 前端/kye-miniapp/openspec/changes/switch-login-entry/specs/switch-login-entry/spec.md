# Spec: switch-login-entry

## ADDED Requirements

### Requirement: 我的页面客户支持区域展示切换登录入口

系统 SHALL 在各端【我的】页面客户支持区域展示【切换登录】轻应用入口，入口数据来源于后台轻应用配置（微信端区域编码 `A6104`、支付宝端区域编码 `A5104`），入口名称固定为「切换登录」，前端通过 `menuName === '切换登录'` 特判命中专属跳转链路。

#### Scenario: 已配置时展示入口（weapp / alipay）

- **WHEN** 后台在客户支持区域配置了 `menuName = '切换登录'` 的轻应用项，用户进入【我的】页面
- **THEN** 客户支持区域九宫格展示「切换登录」入口，图标与文案与配置一致

#### Scenario: 未配置时不展示入口（weapp / alipay）

- **WHEN** 后台未在客户支持区域配置「切换登录」轻应用项
- **THEN** 客户支持区域不展示该入口，页面其余入口展示不受影响

#### Scenario: 支付宝未登录用户可见性（alipay）

- **WHEN** 支付宝端未登录用户进入【我的】页面
- **THEN** 「切换登录」入口不被 `filteAlipayNoLoginApp` 未登录过滤逻辑误删，入口正常展示（未登录点击按登录分流处理）

### Requirement: 入口点击按登录态分流

系统 SHALL 在用户点击【切换登录】入口时按本地登录态分流：已登录用户直接进入切换登录手机号页面；未登录用户先进入登录页，登录成功后自动进入切换登录手机号页面。分流复用统一登录拦截 `kyeNavigate.checkLogin` 与登录成功回跳 `loginBackFn` 机制，不新增独立守卫。

#### Scenario: 已登录直达切换页

- **WHEN** 已登录用户点击【切换登录】入口
- **THEN** 系统直接跳转 `/modules/user/pages/changeLogin/index`（携带 `url` 与 `needLogin=true` 参数），进入切换登录手机号页面

#### Scenario: 未登录先登录再进入（点击事件埋点）

- **WHEN** 未登录用户点击【切换登录】入口
- **THEN** 系统先上报 `clk_home_function_button` 点击埋点（`button_name = 切换登录`），随后进入登录页；登录成功后自动经回跳回调进入切换登录手机号页面

#### Scenario: 登录取消或失败

- **WHEN** 未登录用户在登录页取消或登录失败
- **THEN** 系统停留登录页，用户可返回我的页面，不发生页面错乱或重复打开登录页

### Requirement: 切换登录成功账号状态全局生效

系统 SHALL 在用户于切换登录手机号页面选择非当前登录手机号并完成切换后，以目标账号完成登录：替换本地登录态（token/用户信息），清理全局用户数据缓存，重新拉取轻应用列表等全局配置，并通过 `GLOBAL_SWITCH_USER` 事件通知业务模块刷新，返回【我的】页面展示新账号数据。

#### Scenario: 切换成功全局生效

- **WHEN** 用户在切换登录手机号页面点击非当前登录手机号卡片且切换接口成功，H5 页面回传 `postMessage.loginInfo`
- **THEN** 系统执行 `loginSuccess(loginInfo, { forceClear: true })` 替换登录态并清理全局用户数据，触发 `GLOBAL_SWITCH_USER` 事件，业务模块按既有 token/userInfo 变更监听机制重拉数据，用户返回【我的】页面展示新账号数据

#### Scenario: 目标账号开启禁止他人切换

- **WHEN** 目标手机号账号开启「手机号禁止他人切换」，用户点击该账号卡片
- **THEN** 系统按现有规则完成校验（如短信验证码）后方可切换登录，校验未通过不切换

### Requirement: 切换失败保持原登录态

系统 SHALL 在切换登录接口报错、校验未通过或网络异常时保持当前登录态与页面数据不变，不发生账号替换，并给出失败提示与重试出口。

#### Scenario: 切换接口失败

- **WHEN** 切换登录请求失败或网络异常
- **THEN** 系统保持原登录态不变，提示失败原因并提供重试出口，用户可返回我的页面

#### Scenario: 切换页数据加载失败

- **WHEN** 切换登录手机号页面账号列表加载失败
- **THEN** 页面展示错误占位并提供【重新加载】出口；加载中展示加载态，账号列表为空时展示空态文案与【+ 添加登录手机号】入口

### Requirement: 入口点击埋点上报

系统 SHALL 在用户点击【切换登录】入口时复用「我的页面轻应用点击事件」`clk_home_function_button` 上报，属性 `button_name` 值为「切换登录」，`menu_name` 为所属区域名（如「客户支持」），无需新增埋点事件编码。

#### Scenario: 点击入口上报埋点（点击事件）

- **WHEN** 用户点击【切换登录】入口
- **THEN** 系统上报 `clk_home_function_button` 事件，属性 `button_name = 切换登录`、`page_code = page_home_mine`、`menu_name = 客户支持`

### Requirement: 原有切换手机号入口保持不变

系统 SHALL 保持原有【切换手机号】入口（设置页等既有链路）及其接口、交互与线上现状一致，本次仅新增入口不做下线或迁移。

#### Scenario: 原入口可用

- **WHEN** 用户通过原有【切换手机号】入口进入切换链路
- **THEN** 页面、接口、交互行为与线上现状一致，不受新入口影响
