## 二、路由记录字段（ExtendedRouteRecordRaw）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `path` | `string` | 路由路径。iframe 路由统一以 `/admin` 开头，作为 admin 布局的子路由 |
| `name` | `string` | 路由名。**建议必填**：未配置时 iframe 预加载机制会用 path（去掉 `/`）兜底，且影响页签刷新等能力 |
| `component` | `RouteComponent \| Lazy` | 基座本地页面组件（懒加载或同步导入） |
| `iframeComponent` | `RouteComponent` | iframe 子应用组件，**与 `component` 二选一**。见下文「iframeComponent 说明」 |
| `children` | `ExtendedRouteRecordRaw[]` | 子路由 |
| `redirect` | `string` | 重定向目标 |
| `meta` | `RouteMetaAuth` | 路由元信息，见下节 |

> `iframeComponent` 未包含在 types.ts 的显式类型里，通过 `& Record<string, unknown>` 兼容；实际消费方为 [useRoutePrefetch.ts](file:///Users/kye/Documents/KYE-WORK/PC/netc-pc-web-admin/src/views/admin/hooks/useRoutePrefetch.ts)。

## 三、meta 配置项（RouteMetaAuth）

### 3.1 页面标识类

| 属性 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `name` | `string` | 页面/页签显示名，tabs 组件优先取 `meta.name` 作为标题 | `name: '查看他人运单'` |
| `pageCode` | `string` | 埋点页面编码 | `pageCode: 'page_homepage_v1'` |
| `category` | `string` | 菜单分类标记（如 `基础页面`、`微前端`），用于菜单/调试展示 | `category: '基础页面'` |
| `tabParentPath` | `string` | 页签归属的父路径：该页面打开时页签挂在指定父路由的页签下 | `tabParentPath: '/admin/home'` |

### 3.2 权限控制类（由 guard.ts 守卫管道消费）

| 属性 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `auth` | `string \| string[]` | 所需权限（menuCode 或权限码）。数组 = 任一满足即可；**不配置 = 登录即可访问** | `auth: 'M9999'` |
| `authParam` | `string` | 从路由 param 动态取权限码（`meta.auth` 优先于 `authParam`） | `authParam: 'code'`（配合 `/admin/iframe/:code`） |
| `anonymous` | `boolean` | 免登录路由（如 403、登录中转页），守卫白名单直接放行 | `anonymous: true` |
| `requireCustomerCode` | `boolean` | 需绑定客户编码才能访问，未绑码触发绑码引导弹窗 | `requireCustomerCode: true` |
| `requireOrderPermission` | `boolean` | 需下单权限（`getOrderTips` 校验，`blockedFlag` 时弹「立即申请/审核中」弹窗） | `requireOrderPermission: true` |

> 权限校验顺序：④ 绑码校验 → ⑤ 下单权限 → ⑧ menuCode 权限；数据接口超时 3s 时降级放行（可用性优先，后端仍有鉴权兜底）。

### 3.3 加载策略类

| 属性 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `preload` | `boolean` | 仅对 iframe 路由生效：`true` = admin 布局挂载时立即初始化组件并保持存活（预加载）；`false`/未配置 = 路由激活时才懒加载 | `preload: false` |
| `microApp` | `{ url: string }` | 微前端（micro-app）子应用配置，配合本地容器组件使用 | `microApp: { url: 'https://...' }` |

> iframe 组件一旦被访问（打开 tab）即保持存活，关闭 tab 才销毁，与 keepAlive 配置无关。

## 四、三类路由形态与写法示例

### 4.1 基座内部路由（component）

```ts
{
  name: 'homePage',
  path: '/admin/home',
  component: () => import(/* webpackChunkName: 'home' */ '@/views/home/index2.vue'),
  meta: {
    name: '首页',
    pageCode: 'page_homepage_v1',
    category: '基础页面',
  },
}
```

### 4.2 iframe 子应用路由（iframeComponent）

```ts
import { defineAsyncComponent } from 'vue'

{
  name: 'waybill-v3',
  path: '/admin/waybill-v3',
  // defineAsyncComponent 懒加载异步组件；webpackChunkName 指定分包名
  iframeComponent: defineAsyncComponent(
    () => import(/* webpackChunkName: 'micro-waybill-v3' */ '@/views-iframe/waybill/index.vue')
  ),
  // 需要页签标题 / 权限控制时才配 meta
  meta: { name: '查看他人运单' },
}
```

- 运行时机制（useRoutePrefetch）：
  - 启动时扫描 `/admin` 下所有带 `iframeComponent` 的路由，登记到 iframe 注册表；
  - `meta.preload === true` 的路由立即注册全局组件并预渲染，其余在路由首次激活时懒加载；
  - iframe 页面以 `v-show` 切换保活，tab 关闭时销毁，重开时重建。

### 4.3 微前端子应用路由（microApp）

```ts
{
  name: 'order',
  path: '/admin/order',
  component: () => import(/* webpackChunkName: 'micro-app' */ '@/views-micro/order-config/index.vue'),
  meta: {
    name: '微应用',
    category: '微前端',
    microApp: { url: 'https://uc-uat.ky-express.com/web-order-config/0.252.10/#/order' },
  },
}
```

### 4.4 动态 iframe 路由（authParam）

```ts
{
  name: 'iframe-code',
  path: '/admin/iframe/:code',
  iframeComponent: defineAsyncComponent(
    () => import(/* webpackChunkName: 'micro-iframe-code' */ '@/views-iframe/iframe/code-iframe.vue')
  ),
  meta: {
    // :code 即菜单 menuCode，权限码从 param 取（菜单存在即有权限，防 URL 手输绕过）
    authParam: 'code',
  },
}
// 跳转方式：router.push({ name: 'iframe-code', params: { code: '菜单编码' } })
```

### 4.5 业务权限组合（寄件类页面典型配置）

```ts
{
  name: 'order-create',
  path: '/admin/order-create',
  iframeComponent: defineAsyncComponent(
    () => import(/* webpackChunkName: 'micro-order' */ '@/views-iframe/order/index.vue')
  ),
  meta: {
    preload: false,
    // 寄件路由：需绑码 + 下单权限（守卫管道 ④绑码 → ⑤下单权限）
    requireCustomerCode: true,
    requireOrderPermission: true,
  },
}
```

## 五、路由守卫要点（guard.ts）

守卫管道按序执行，返回 `true` 放行 / `false` 中止留原页 / string 重定向：

1. **⓪ 404 补偿跳转**：未匹配路径落 404 时，若原始路径可映射到已注册子应用容器，重定向到容器路由并携带 `realRoutePath` + `timeStamp` query。
2. **① 免登录放行**：`WHITE_LIST`（如 `notFound`）或 `meta.anonymous === true`。
3. **② 登录校验**：无 token 跳统一登录（本地开发提示手动获取 token）。
4. **③ 按需阻塞**：仅当路由声明了权限/绑码/下单标记才等待对应 store 数据（3s 超时降级放行），无标记路由零阻塞；未依赖的数据后台预热。
5. **④⑤ 业务权限**：`requireCustomerCode` → 绑码弹窗；`requireOrderPermission` → 下单权限弹窗。
6. **⑦⑧ menuCode 权限**：`meta.auth` / `meta.authParam` 校验，无权限弹窗拦截；权限数据不可用时放行并埋点告警。

## 六、404 与兜底规则

| 场景 | 处理 |
| --- | --- |
| 顶层未匹配 | 命中 `/:pathMatch(.*)*` → `notFound`（免登录白名单） |
| `/admin` 下未匹配子路径 | 命中 admin 子级 catch-all → 重定向 `/admin/404`（`adminNotFound`） |
| 未注册的子应用二级路径（如 `/admin/user/xxx`） | 守卫按前缀映射重写到对应 iframe 容器路由，附加 `realRoutePath`、`timeStamp` 交由子应用二级导航；目标容器未注册时不重写（维持 404，防死循环） |

## 七、新增路由检查清单

- [ ] 放到 `iframe/` 对应业务域文件（或 `internal/` / `micro-app/`），并在 `iframe/index.ts` 聚合
- [ ] `name` 与 `path` 唯一，path 以 `/admin` 开头
- [ ] iframe 组件使用 `defineAsyncComponent` + `webpackChunkName` 分包注释
- [ ] 按[url权限方案](./路由权限方案.md)确认是否需要 `auth` / `requireCustomerCode` / `requireOrderPermission`
- [ ] 需要页签标题的配置 `meta.name`；埋点页面配置 `meta.pageCode`
- [ ] 高频页面可评估 `meta.preload: true`（首屏代价换体验）
- [ ] 守卫白名单/映射表（`WHITE_LIST`、`REDIRECT_PATH_LISTS`、`MICRO_CONTAINER_REDIRECT_MAP`）如需改动请同步更新
