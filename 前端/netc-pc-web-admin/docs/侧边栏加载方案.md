# 侧边栏菜单加载方案

## 背景

侧边栏菜单数据来源于区域菜单接口 `web.lightApplication.getApplicationInfoListByArea`。原方案存在以下问题：

1. 无缓存首次进入时，菜单区域完全空白，无任何加载反馈
2. 接口失败被 catch 吞掉，用户无法感知失败，也无法重试
3. 无兜底数据，接口异常时侧边栏不可用

## 方案设计

整体链路：**缓存 → 接口 → defaultData 兜底 → 失败重试 UI**

```
进入页面（App.vue 启动时调用 lightAppStore.init()）
  │
  ├─ 读取 localStorage 缓存（lightAppCache）
  │    └─ 有缓存 → 直接渲染菜单，后台静默刷新接口
  │
  ├─ 无缓存 → 骨架屏（loading），等待接口
  │    ├─ 成功 → 渲染菜单 + 写入缓存
  │    └─ 失败 → 使用本地 defaultData 兜底渲染
  │              └─ defaultData 也为空 → 失败态，可点击重新加载
  │
  └─ 有缓存但刷新失败 → 继续展示缓存菜单，不打扰用户
```

## 状态模型

Store 暴露 `menuStatus` 计算属性，三态驱动组件渲染：

| 状态      | 条件                                       | UI 表现                        |
| --------- | ------------------------------------------ | ------------------------------ |
| `success` | `menusList` 有数据（含缓存 / 接口 / 兜底） | 正常 el-menu 渲染              |
| `loading` | 无数据且未标记失败                         | 菜单形骨架屏                   |
| `error`   | 无数据且接口失败、兜底数据为空             | 「菜单加载失败」+ 重新加载按钮 |

关键规则：**有数据（含缓存）即 success**，实现缓存/兜底静默降级，接口失败不打扰用户。

## Store 层实现（lightapp.ts）

### 状态定义

```ts
const isLoading = ref(false) // 接口请求中
const loadError = ref(false) // 接口失败标记

const menuStatus = computed<'loading' | 'success' | 'error'>(() => {
  if (menusList.value.length > 0) return 'success'
  return loadError.value ? 'error' : 'loading'
})
```

### init 流程

```ts
async function init() {
  if (initPromise) return initPromise // promise 去重，多调用点共享一次请求

  loadCache() // 1. 优先从缓存加载，页面尽快展示

  initPromise = (async () => {
    try {
      await microApplicationListGet() // 2. 后台静默刷新
    } catch (error) {
      console.error('获取轻应用列表失败:', error)
    } finally {
      isLoading.value = false
      initPromise = null // 失败后置空，支持重试
    }
  })()

  if (lightAppList.value.length > 0) return // 3. 有缓存不阻塞，无缓存等接口
  await initPromise
}
```

要点：

- **promise 去重**：`App.vue` 与 `menu/index.vue` 都会调用 `init()`，通过 `initPromise` 保证只发一次请求
- **失败可重试**：`initPromise` 在 `finally` 中置空，失败后再次调用 `init()` 即重新发起请求，无需额外重试方法

### 接口失败降级

```ts
catch (error) {
  loadError.value = true
  console.error('获取轻应用列表失败:', error)
  applyFallbackMenu()   // 使用本地 defaultData 兜底
}

function applyFallbackMenu() {
  defaultData.forEach(({ areaCode, lightApplicationInfos }) => {
    appLightAppinfo.value.set(areaCode, lightApplicationInfos)
  })
  // 重新推导 menusList / lightAppList（与接口成功路径一致）
}
```

要点：

- **不写缓存**：兜底数据不执行 `saveCache()`，避免污染 localStorage，下次刷新仍优先尝试真实接口
- **复用推导逻辑**：与接口成功路径相同地推导 `menusList` / `lightAppList`

### 缓存策略

- key：`lightAppCache`，存储 `appLightAppinfo` 的 entries 数组
- 写入时机：仅接口成功后写入
- 读取时机：`init()` 时优先读取，秒显菜单
- 容错：读写均 try-catch，失败静默忽略

## 组件层实现（menu/index.vue）

### 组件定位

侧边栏菜单 UI 组件，位于 `src/views/admin/components/menu/index.vue`，职责：

- 按 `menuStatus` 三态渲染（骨架屏 / 失败重试 / 正常菜单）
- 渲染最多两级菜单（父级 `el-sub-menu` + 子级 `el-menu-item`，无子级直接渲染 `el-menu-item`）
- 激活态高亮（含父级联动）、图标切换（默认/选中）
- 路径规范化（兼容 `#/home`、`admin/home` 等格式）
- 折叠/展开控制（由父组件 `useLayout` 管理，通过 props 传入）

### Props

```ts
interface MenuProps {
  /** 是否折叠（控制 el-menu collapse 及骨架屏文字显隐） */
  isCollapse: boolean
  /** 折叠状态切换回调（底部 handle-btn 触发） */
  handleCollapse: (bol: boolean) => void
}
```

### 渲染结构

```html
<div id="menu">
  <div id="menu-content" class="menu">
    <!-- loading：菜单骨架屏（8 个「图标+文字条」项，折叠态隐藏文字） -->
    <div v-if="menuStatus === 'loading'" class="menu-skeleton">
      <el-skeleton animated>
        <template #template>
          <div v-for="i in 8" :key="i" class="skeleton-item">
            <el-skeleton-item variant="image" class="skeleton-icon" />
            <el-skeleton-item v-if="!isCollapse" variant="text" class="skeleton-text" />
          </div>
        </template>
      </el-skeleton>
    </div>

    <!-- error：失败重试（无缓存且接口失败、兜底为空的极端场景） -->
    <div v-else-if="menuStatus === 'error'" class="menu-error">
      <div class="menu-error-text">菜单加载失败</div>
      <el-button type="primary" size="small" @click="refreshMenu">重新加载</el-button>
    </div>

    <!-- success：正常菜单（有数据即渲染，含缓存秒显 / defaultData 兜底） -->
    <el-menu v-else :default-active="activeMenu" :collapse="isCollapse" @select="handleSelect">
      <template v-for="item in menusList" :key="item.menuCode">
        <!-- 有子菜单：父级 + 子级两级渲染 -->
        <el-sub-menu v-if="item.subMenus?.length" :index="item.menuCode">
          <template #title>
            <img :src="menuIconSrc(item, isParentActive(item))" class="menu-icon" />
            <span class="menu-text">{{ item.menuName }}</span>
          </template>
          <el-menu-item
            v-for="child in item.subMenus"
            :key="child.menuCode"
            :index="normalizePath(child.path || child.routePath)"
          >
            <img :src="menuIconSrc(child, isActive(child))" class="menu-icon" />
            <span class="menu-text">{{ child.menuName }}</span>
          </el-menu-item>
        </el-sub-menu>
        <!-- 无子菜单：叶子节点直接渲染 -->
        <el-menu-item v-else :index="normalizePath(item.path || item.routePath)">
          <img :src="menuIconSrc(item, isActive(item))" class="menu-icon" />
          <span class="menu-text">{{ item.menuName }}</span>
        </el-menu-item>
      </template>
    </el-menu>
  </div>
  <!-- 底部折叠/展开开关 -->
  <div id="menu-handle-btn" @click="handleClick"></div>
</div>
```

### 脚本逻辑

```ts
const menusList = computed(() => lightAppStore.menusList) // 菜单数据（store 驱动）
const menuStatus = computed(() => lightAppStore.menuStatus) // 三态：loading / error / success
const activeMenu = computed(() => route.path) // 激活项 = 当前路由

/** 失败重试（initPromise 失败后已置空，可重新发起请求） */
const refreshMenu = () => lightAppStore.init()

/** 路径规范化：去除 # 前缀、补 / 前缀（兼容 '#/home'、'admin/home'） */
const normalizePath = (path: string) => {
  if (!path) return ''
  const clean = path.replace(/^#/, '')
  return clean.startsWith('/') ? clean : `/${clean}`
}

/** 图标选择：激活用 activeIcon，依次降级 defaultIcon → menuIcon */
const menuIconSrc = (item: MenuItem, active: boolean) =>
  active ? item.activeIcon || item.defaultIcon || item.menuIcon || '' : item.defaultIcon || item.menuIcon || ''

/** 叶子激活：路由 path 与菜单路径一致 */
const isActive = (item: MenuItem) => route.path === normalizePath(item.path || item.routePath)

/** 父级联动激活：任一子菜单激活则父级高亮 */
const isParentActive = (item: MenuItem) => item.subMenus?.some(isActive) ?? false

/** 菜单选择：index 即规范化后的路径，直接 router.push */
const handleSelect = (index: string) => router.push(index)

/** 底部按钮：切换折叠状态 */
const handleClick = () => props.handleCollapse(!props.isCollapse)

onMounted(() => lightAppStore.init()) // 与 App.vue 调用点经 initPromise 去重
```

### 样式要点（index.scss）

| 类名                        | 说明                                                        |
| --------------------------- | ----------------------------------------------------------- |
| `#menu-content`             | 高度 `calc(100% - 32px)`，纵向滚动（`@include scroll-bar`） |
| `#menu-handle-btn`          | 底部 32px 折叠开关区域，上边框分隔                          |
| `.menu-icon` / `.menu-text` | 16px 图标 + 13px 文字，间距 10px                            |
| `.menu-skeleton`            | 骨架屏：每项高 40px，图标 16px + 文字条 90x13px             |
| `.menu-error`               | 失败态：纵向居中，文案 13px 灰色 + 76x24 重试按钮           |

样式适配侧栏宽度（展开 160px / 折叠 64px，宽度过渡由父级 `#menu-wrap` 的 `transition` 完成），失败态为紧凑布局。

### 数据流

```
useLightAppStore（menusList / menuStatus）
        │ computed
        ▼
menu/index.vue ── select ──► router.push(index)
        ▲                       │
        │ props                 ▼
useLayout（isCollapse / handleCollapse）   route.path ──► activeMenu / isActive
```

组件本身不发起请求（仅 mounted 兜底调用一次 `init()`，与 App.vue 调用去重），所有数据与状态均来自 store，保证多组件实例间状态一致。

## 各场景行为汇总

| 场景                         | 行为                                           |
| ---------------------------- | ---------------------------------------------- |
| 有缓存 + 接口成功            | 秒显缓存菜单 → 静默更新 + 刷新缓存             |
| 有缓存 + 接口失败            | 秒显缓存菜单，不受影响（仅控制台记录）         |
| 无缓存 + 接口成功            | 骨架屏 → 渲染菜单 + 写缓存                     |
| 无缓存 + 接口失败            | 骨架屏 → defaultData 兜底渲染                  |
| 无缓存 + 接口失败 + 兜底为空 | 骨架屏 → 失败态 → 点击重新加载                 |
| 点击重新加载                 | 重新走 init 流程（promise 已置空，会重新请求） |

## 后续可选增强

1. **缓存用户维度**：`lightAppCache` 目前无用户标识，多账号同浏览器切换可能串菜单，可在 key 中拼接用户 code
2. **兜底数据版本化**：`defaultData` 随发版更新，可考虑与 shellVersion 关联
3. **降级上报**：接口失败触发兜底时可通过已有的 ump 埋点上报降级事件，量化兜底命中率
