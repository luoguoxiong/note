# 框架侧边栏技术方案

## 1. 概述

侧边栏是本框架（netc-pc-web-admin，主应用壳）的核心导航容器，由后端「区域菜单」接口统一驱动，负责：

- 渲染两级导航菜单（轻应用入口），点击后通过路由跳转激活对应页面 / iframe 微应用
- 提供「缓存秒显 → 静默刷新 → 本地兜底 → 失败重试」的高可用加载链路
- 支持折叠 / 展开的布局形态切换

技术栈：Vue 3（`<script setup>` + TS）+ Pinia + Element Plus（`el-menu` / `el-skeleton`）。

## 2. 整体架构

```
┌─────────────────────────── 布局层 ───────────────────────────┐
│ admin/index.vue      #menu-wrap（160px/64px，宽度过渡动画）      │
│                      └─ menu/index.vue        ← useLayout     │
├─────────────────────────── 组件层 ───────────────────────────┤
│ menu/index.vue       三态渲染 / 两级菜单 / 激活态 / 折叠按钮     │
│ menu/index.scss      骨架屏、失败态、菜单项样式                  │
│ menu/el-reset.scss   Element Plus 菜单样式覆写                 │
├─────────────────────────── 状态层 ───────────────────────────┤
│ stores/lightapp.ts   Pinia store：init / 缓存 / 兜底 / 状态暴露 │
│ stores/mock.ts       MenuItem 类型定义 + defaultData 兜底数据   │
├─────────────────────────── 数据源层 ──────────────────────────┤
│ apis/lightapp        web.lightApplication.getApplicationInfoListByArea      │
│ mock/同名.js         开发环境 mock                             │
└──────────────────────────────────────────────────────────────┘
```

设计原则：**单向数据流**——组件不直接发起请求（仅 mounted 兜底调用 `init()`），所有数据与状态来自 store，保证多调用点（App.vue / Menu / Tabs）状态一致。

## 3. 数据模型

### 3.1 区域模型（areaCode）

接口按「区域」返回菜单集合，本框架侧边栏固定消费区域编码 `A8001`（`AppAreaCodes.SlideAreaCode`）。区域模型使同一份数据可同时服务侧边栏、头部等多个展示区域。

```ts
enum AppAreaCodes {
  'SlideAreaCode' = 'A8001',
}
```

### 3.2 核心类型（MenuItem，定义于 stores/mock.ts）

| 字段                                      | 说明                                           |
| ----------------------------------------- | ---------------------------------------------- |
| `menuCode` / `menuName`                   | 菜单编码（唯一 key）、名称                     |
| `path` / `routePath`                      | 跳转地址（两种来源格式，见 5.3 路径规范化）    |
| `defaultIcon` / `activeIcon` / `menuIcon` | 图标三级降级（默认 → 选中 → 兜底）             |
| `loadAddress` + `versionNumber`           | 微应用静态资源地址与版本（拼接出完整应用 URL） |
| `subMenus?: MenuItem[]`                   | 子菜单（最多两级）                             |
| `grayHeader` / `needGray`                 | 灰度信息，透传给微应用                         |

### 3.3 数据推导

接口返回 `data.vos: [{ areaCode, menus }]`，写入 `appLightAppinfo: Map<areaCode, MenuItem[]>` 后推导出两个视图数据：

- `menusList`：侧边栏树形数据（父级含 `subMenus`）
- `lightAppList`：拍平后的叶子节点列表，进一步生成 `lightAppMap`（menuCode → item），供 Tabs、iframe 桥接等模块按 code 检索应用地址（`getAppUrl` / `microMenuRouteUrl`）

推导逻辑在「接口成功 / 缓存读取 / 兜底降级」三条路径中复用，保证数据形态一致。

## 4. 状态层设计（stores/lightapp.ts）

### 4.1 状态定义

```ts
const menusList = ref<MenuItem[]>([]) // 树形菜单
const lightAppList = ref<MenuItem[]>([]) // 拍平叶子
const appLightAppinfo = ref<Map<string, MenuItem[]>>() // 区域 → 菜单
const isLoading = ref(false) // 请求中
const loadError = ref(false) // 失败标记
let initPromise: Promise<void> | null = null // 模块级去重（非响应式）
```

### 4.2 状态模型 menuStatus

```ts
const menuStatus = computed<'loading' | 'success' | 'error'>(() => {
  if (menusList.value.length > 0) return 'success'
  return loadError.value ? 'error' : 'loading'
})
```

| 状态      | 条件                                             | UI                |
| --------- | ------------------------------------------------ | ----------------- |
| `success` | `menusList` 有数据（缓存 / 接口 / 兜底任一来源） | 正常 el-menu      |
| `loading` | 无数据且未失败                                   | 骨架屏            |
| `error`   | 无数据且接口失败且兜底为空                       | 失败态 + 重试按钮 |

关键规则：**有数据即 success**——实现缓存 / 兜底的静默降级，接口失败不打扰用户。

### 4.3 init 流程（promise 去重 + 非阻塞）

```ts
async function init() {
  if (initPromise) return initPromise   // 多调用点共享一次请求
  loadCache()                           // ① 缓存优先，秒显
  initPromise = (async () => {
    try { await microApplicationListGet() }   // ② 后台静默刷新
    catch (error) { console.error(...) }
    finally { isLoading.value = false; initPromise = null }  // ③ 失败置空 → 支持重试
  })()
  if (lightAppList.value.length > 0) return  // 有缓存不阻塞
  await initPromise                          // 无缓存等接口
}
```

- **去重**：App.vue、menu/index.vue、tabs/index.vue 三处调用 `init()`，仅发一次请求
- **可重试**：`initPromise` 在 finally 置空，失败态点击「重新加载」即再次调用 `init()`，无需独立重试方法

### 4.4 容错与降级

```
接口成功 → 数据落 store + saveCache() → loadError = false
接口失败 → loadError = true → applyFallbackMenu()（defaultData 兜底）
```

兜底规则：

- **兜底数据不写缓存**：避免污染 localStorage，下次刷新仍优先尝试真实接口
- **兜底数据结构对齐接口 `vos`**：复用同一套推导逻辑
- 缓存读写均 try-catch 静默容错（隐私模式 / 存储超限等场景不致命）

### 4.5 缓存策略

| 项   | 说明                                        |
| ---- | ------------------------------------------- |
| key  | `lightAppCache`（LocalStorageManager 管理） |
| 内容 | `appLightAppinfo` 的 entries 数组           |
| 写入 | 仅接口成功后                                |
| 读取 | `init()` 最先执行，命中即秒显菜单并静默刷新 |

## 5. 组件层设计（menu/index.vue）

### 5.1 组件定位与 Props

纯展示 + 交互组件，无自治数据。折叠状态由父级 `useLayout` 管理并通过 props 传入：

```ts
interface MenuProps {
  isCollapse: boolean // 控制 el-menu collapse 及骨架屏文字显隐
  handleCollapse: (bol: boolean) => void
}
```

### 5.2 渲染结构

```
#menu
 ├─ #menu-content（纵向滚动，高 calc(100% - 32px)）
 │   ├─ loading  → el-skeleton 骨架屏（8 项「图标+文字条」，折叠态隐藏文字条）
 │   ├─ error    → 「菜单加载失败」+ 重新加载按钮
 │   └─ success  → el-menu（:default-active + :collapse + @select）
 │        ├─ 有 subMenus → el-sub-menu + 子 el-menu-item（两级）
 │        └─ 无 subMenus → 叶子 el-menu-item
 └─ #menu-handle-btn（底部 32px 折叠/展开开关）
```

### 5.3 关键交互逻辑

| 逻辑           | 实现                                                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **路径规范化** | `normalizePath`：去 `#` 前缀、补 `/` 前缀，兼容 `#/home`、`admin/home` 两种数据格式，同时用作 el-menu index 与激活匹配 |
| **导航**       | `@select` 中 `router.push(index)`，index 即规范化路径                                                                  |
| **激活态**     | 叶子：`route.path === normalizePath(...)`；父级联动：任一子菜单激活则父级高亮（驱动选中图标切换）                      |
| **图标降级**   | `activeIcon → defaultIcon → menuIcon`，激活/非激活两套取值                                                             |
| **失败重试**   | `refreshMenu()` 直接调用 `store.init()`（promise 已置空会重新请求）                                                    |
| **折叠**       | 底部按钮触发 `props.handleCollapse(!isCollapse)`，宽度动画由父级 `#menu-wrap` 的 `transition` 完成                     |

### 5.4 布局与样式

| 选择器                      | 说明                                                     |
| --------------------------- | -------------------------------------------------------- |
| `#menu-wrap`                | 展开 160px / 折叠 64px，`transition: width 0.5s ease-in` |
| `#menu-content`             | `@include scroll-bar` 自定义滚动条                       |
| `.menu-icon` / `.menu-text` | 16px 图标 + 13px 文字，间距 10px                         |
| `.menu-skeleton`            | 每项高 40px（16px 图标 + 90×13px 文字条）                |
| `.menu-error`               | 纵向居中紧凑布局，76×24 重试按钮                         |
| `el-reset.scss`             | 覆写 Element Plus 菜单默认样式（背景色、圆角、hover 等） |

## 6. 端到端流程

```
应用启动
  └─ App.vue → store.init()
       ├─ 读 lightAppCache ──命中──► 秒显菜单 ──┐
       └─ 未命中 → 骨架屏                        │
            ├─ 接口成功 → 渲染 + 写缓存 ◄─静默刷新─┘
            ├─ 接口失败 → defaultData 兜底渲染（不写缓存）
            └─ 兜底为空 → 失败态 → 重新加载 → 重走 init

用户点击菜单
  └─ handleSelect(normalizedPath) → router.push
       ├─ 本地路由 → router-view / keep-alive
       └─ iframe 路由 → useRoutePrefetch 懒加载 iframe 组件（打开即存活，关 tab 销毁）
```

## 7. 与周边模块的关系

| 模块                        | 关系                                                                                              |
| --------------------------- | ------------------------------------------------------------------------------------------------- |
| Tabs（页签）                | 共享 `store.init()` 与 `lightAppList`；`iframePaths` 用于排除内部页面重复 tab                     |
| useRoutePrefetch            | 管理菜单跳转目标中 iframe 类页面的懒加载 / 预加载与存活策略                                       |
| iframe 桥接（views-iframe） | 通过 `lightAppMap` 按 menuCode 获取 `loadAddress + routePath`，拼接 token / grayHeader 打通微应用 |
| useLayout                   | 侧边栏折叠状态的唯一数据源，菜单组件只读消费                                                      |

## 8. 场景行为矩阵

| 场景                     | 行为                                          |
| ------------------------ | --------------------------------------------- |
| 有缓存 + 接口成功        | 秒显缓存 → 静默更新 + 刷新缓存                |
| 有缓存 + 接口失败        | 秒显缓存，不受影响（仅控制台记录）            |
| 无缓存 + 接口成功        | 骨架屏 → 菜单 + 写缓存                        |
| 无缓存 + 接口失败        | 骨架屏 → defaultData 兜底                     |
| 无缓存 + 失败 + 兜底为空 | 骨架屏 → 失败态 → 重新加载                    |
| 折叠/展开                | 64px ↔ 160px 宽度过渡，骨架屏文字条随折叠隐藏 |

## 10. 后续演进

1. **缓存用户维度**：`lightAppCache` 无用户标识，多账号同浏览器切换可能串菜单，可在 key 中拼接用户 code
2. **兜底数据版本化**：`defaultData` 随发版更新，可与应用 shellVersion 关联，避免旧兜底数据指向已下线版本
3. **降级上报**：接口失败触发兜底时通过 ump 埋点上报降级事件，量化兜底命中率
4. **菜单权限细化**：目前菜单完全由后端区域接口控制，可增加前端路由级守卫兜底校验
5. **缓存过期策略**：当前缓存永不过期（仅被成功响应覆盖），可增加 TTL 或版本号比对，降低脏缓存长期驻留风险
