# 微模块接入指南（netc-pc-web-admin）

> 微模块（自研微前端 `@kye-netc/micro-module`）是区别于 iframe 的"注入式"微应用方案：子应用构建为单入口 JS，由基座沙箱加载执行，**路由与视图直接渲染在基座 `<router-view>` 下**，与基座共享 Vue / Element Plus 运行时。本文说明一个新微模块在基座侧与子应用侧的完整接入步骤。
>
> 区分三种页面承载方式：
>
> | 方式 | 机制 | 适用 |
> | --- | --- | --- |
> | **微模块（本文）** | 沙箱加载子应用 JS，共享运行时，路由注入 | 需要深度共享组件 / 依赖、体验要求高的原生页面 |
> | 京东 micro-app | `<micro-app>` WebComponent 容器 | 存量接入（如 order-config），新模块不建议 |
> | iframe | URL 拼接 + iframeBridge / storeBridge 通信 | 老项目页面，见 `路由配置说明.md` |

## 1. 整体架构

```
基座 main.ts
  └─ createMicroMainApp(App, { microApps: [...] })      # 注册微模块清单
       ├─ loader（@kye-netc/micro-module）
       │    ├─ resolveEntry: 拉取子应用 manifest.json → 解析带 hash 的 js/css 入口
       │    └─ ProxySandbox: fetch 代码 + execInSandbox 执行，注入 fakeWindow
       └─ micro-router（@kye-netc/micro-module）
            ├─ beforeEach: 前缀匹配 activeRule → addRoutes 动态注入子应用路由
            └─ afterEach: 生命周期 mount/unmount + 沙箱 activate/deactivate

子应用 main.ts
  └─ registerSubApp({ name, routes, components, ... }, App, null)
       └─ 注入模式：把 { routes, bootstrap, mount, unmount } 写到 window[name]，供基座沙箱读取
```

## 2. 基座侧接入步骤

### 2.1 注册微模块清单

在 [src/main.ts](file:///Users/kye/Documents/KYE-WORK/PC/netc-pc-web-admin/src/main.ts) 的 `createMicroMainApp` 中追加一项：

```ts
export const { app, router } = createMicroMainApp(App as Any, {
  history: VueRouter.createWebHashHistory(),
  routes: routes as Any,
  preload: false, // 浏览器空闲后按 priority 升序预加载所有子应用
  microApps: [
    {
      name: 'order-utils',            // 必须与子应用 registerSubApp 的 name、产物暴露的 window 全局变量名完全一致
      parentRouteName: 'Admin',       // 子应用路由注入到基座哪个路由的 children（Admin 为 /admin 布局）
      entry: Promise.resolve('https://uc-uat.ky-express.com/netc-pc-web-order-utils-new/0.0.4/'),
      // 生产推荐改为菜单动态下发：
      // entry: useLightAppStore(pinia).getAppLoadModuleEntry('M3072'),
      activeRule: '/admin/query',     // 前缀匹配：path 以此开头的路由触发加载该子应用
      priority: 1,                    // 越小预加载越早
    },
  ],
})
```

| 字段 | 说明 |
| --- | --- |
| `name` | 沙箱内全局变量 key（`window['order-utils']`），与子应用暴露名**严格一致** |
| `entry` | 子应用静态资源目录 URL（以 `/` 结尾）。支持传 Promise 以异步解析；loader 会请求 `{entry}manifest.json` 解析真实入口 |
| `activeRule` | 路由前缀，`path.startsWith(rule)` 即命中；命中后按 `parentRouteName` 注入子应用路由 |
| `priority` | `preload: true` 时的预加载顺序 |

### 2.2 菜单数据（生产环境的 entry 来源）

生产环境不写死 entry，由「区域菜单」接口下发（mock 见 [mock/web.lightApplication.getApplicationInfoListByArea.js](file:///Users/kye/Documents/KYE-WORK/PC/netc-pc-web-admin/mock/web.lightApplication.getApplicationInfoListByArea.js)）。微模块菜单条目关键字段（参考 M3072 运费时效查询）：

| 字段 | 示例值 | 用途 |
| --- | --- | --- |
| `menuCode` | `M3072` | 唯一 key，`getAppLoadModuleEntry(menuCode)` 按此取 entry |
| `menuPath` | `/admin/query` | 侧边栏跳转地址，需与基座 `activeRule` 前缀一致 |
| `loadAddress` | `https://uc-uat.ky-express.com/netc-pc-web-order-utils/0.76.10/` | 子应用资源目录 = 微模块 entry |
| `versionNumber` | `0.76.10` | 版本号（与 loadAddress 路径中的版本目录对应） |
| `routePath` | `#/admin/query` | iframe 场景拼接用，微模块场景不消费 |
| `applicationCode` | `PC_WEB_ORDER_UTILS` | 应用编码 |
| `grayHeader` | `[]` | 灰度信息，透传子应用 |

基座 store 封装见 [src/stores/lightapp.ts](file:///Users/kye/Documents/KYE-WORK/PC/netc-pc-web-admin/src/stores/lightapp.ts)：

```ts

getAppUrl('M3072')               // → loadAddress + routePath + token + grayHeader（iframe 场景）
```

### 2.3 路由注入机制（无需手写路由）

子应用路由**不需要**在基座 `src/router/` 中静态注册，由 `micro-router` 的 `beforeEach` 动态完成：

1. 导航发生时，`findMicroAppByPath` 按 `activeRule` 前缀匹配命中的微模块；
2. 从沙箱 `fakeWindow[name]` 读取子应用 `routes`，`addRoutes` 注入到 `parentRouteName`（Admin）的 children，同名路由自动去重；
3. 注入成功后回放原始路径（防止被 `/admin/:pathMatch(.*)*` 的 404 兜底 catch-all 吞掉）；
4. `afterEach` 触发子应用 `mount` / `unmount` 与沙箱 activate / deactivate。

基座侧仅需保证 `activeRule` 前缀不与现有静态路由冲突。

## 3. 子应用侧接入步骤

以 netc-pc-web-order-utils-new（vue-cli + webpack）为例。

### 3.1 构建配置（vue.config.js）

| 配置 | 要求 | 原因 |
| --- | --- | --- |
| `externals` | `vue` / `vue-router` / `vuex` / `pinia` / `element-plus` 五件套走全局变量 | 与基座共享同一实例，避免双份运行时与样式行为差异 |
| `splitChunks: false`、`runtimeChunk: false` | 产物收敛为单入口 `app.js` | loader 只执行 manifest 声明的入口，分包会导致 registerSubApp 不执行 |
| `WebpackManifestPlugin` | 产出 `manifest.json` | 基座 `resolveEntry` 依赖它解析带 hash 的真实入口 |
| `ElementPlusResolver({ importStyle: false })` | 关闭组件库样式自动引入 | Element Plus 全量 CSS 由基座统一提供，重复引入会样式冲突 |
| Element Plus 版本 | 与基座**严格一致**（当前 2.5.6） | 共享实例下版本不一致会出现样式/行为差异 |
| devServer | 允许跨域（CORS） | 本地联调时基座跨域 fetch 子应用代码 |
| `MICRO_DEBUG=1` | 可选 | 本地调试辅助 |

### 3.2 入口文件（src/main.ts）

**第一行**引入 public-path（必须在其它 import 之前）：

```ts
import './public-path' // 沙箱模式读 __SANDBOX_ENTRY_URL__，非沙箱读 document.currentScript，动态设 __webpack_public_path__
```

单产物双模式分流（`registerSubApp` 从 `@kye-netc/micro-module/sub-app` 引入）：

```ts
const isMicro = !!(window as Any).__MICRO_MODULE_ENVIRONMENT__ // loader 执行入口前注入的沙箱标志

if (isMicro) {
  // 注入模式：导出给主应用，禁止传 DOM 元素（主应用也有 #app，会误入独立分支导致 "未暴露 routes"）
  appInstance = registerSubApp(
    {
      name: 'order-utils', // 与基座 microApps.name 完全一致
      routes: microRoutes, // 必须有，缺失会报 "未暴露 routes"
      components: {        // 可选：共享组件表，供基座/其他子应用 useRemoteComponent 懒加载
        'address-block': () => import('@/components/.../address-block/index.vue'),
      },
      bootstrap: async () => undefined,
      mount: () => undefined,
      unmount: () => undefined,
    },
    App,
    null, // 第三个参数传 null 走注入模式；传容器 DOM 则为独立挂载模式
  )
  // 注入模式下仅允许补装：vuex（provide 到宿主，key 为子应用私有 Symbol）、svg-icon
  appInstance.use(store, key)
  appInstance.component('svg-icon', SvgIcon)
  setGrayheader() // 注入模式下 App.vue 不渲染，灰度解析必须在此调用
} else {
  // 独立模式：createApp + 自带全局守卫的 router 实例（守卫含关骨架屏逻辑，缺失会显示"加载超时"）
  appInstance = createApp(App)
  appInstance.use(router)
  installPlugins(appInstance) // 独立模式全量安装插件
  appInstance.mount('#app')
}
```

路由导出要求：导出的 routes 需**拍平为顶层**并统一加 `/admin/` 前缀（基座 Admin 布局路由已存在，同名嵌套注入会被跳过导致子路由丢失）；子应用自身全局守卫不会在注入模式执行，需合并进每条路由的 `beforeEnter`：

```ts
const adminRoute = routes.find((route) => route.name === 'admin')
const microRoutes = (adminRoute?.children ?? []).map((child) =>
  attachCommonGuard({ ...child, path: `/admin/${String(child.path).replace(/^\//, '')}` }),
)
```

externals 依赖强校验（缺失立即报错而非白屏）：

```ts
const requiredGlobals = ['Vue', 'VueRouter', 'Vuex', 'Pinia', 'ElementPlus']
const missing = requiredGlobals.filter((name) => !window[name])
if (missing.length) throw new Error(`缺少 externals 依赖的全局变量: ${missing.join(', ')}`)
```

### 3.3 插件安装红线（注入模式）

| 插件 | 是否可装到宿主 app | 原因 |
| --- | --- | --- |
| Vuex（`app.use(store, key)`） | ✅ 允许 | key 为子应用私有 Symbol，主应用不用 vuex，无冲突 |
| svg-icon 全局组件 | ✅ 允许 | 子应用模板依赖全局解析，不注册图标全 404 |
| **Pinia** | ❌ 严禁 | 覆盖主应用 `provide(piniaSymbol)` 与模块级 `activePinia`，主应用 store 串实例（曾导致权限弹窗不触发） |
| **ReportUmp** | ❌ 严禁 | 主应用已注册同名指令与 aplus SDK，重复 install 会覆盖指令、重复注入 SDK |
| 应用级 `app.use(store)` / 全局 SVG 注册 | ❌ 严禁 | 应用级插件一律不得污染宿主实例 |

补充约束：

- 子应用 Pinia store id 必须**命名空间前缀**（如 `order-utils:freightTime`），避免与主应用及未来其他子应用冲突；
- SVG 图标在路由组件内**局部注册**，不做全局注册；
- 路由守卫仅放在每条导出路由的 `beforeEnter`，不依赖全局 `router.beforeEach`。

## 4. 生命周期与运行时行为

```
用户导航到 /admin/query（命中 activeRule）
  ├─ 首次：resolveEntry（fetch manifest.json）→ fetch 入口 JS/CSS
  │        → 创建 ProxySandbox → execInSandbox 执行子应用 main.ts
  │        → registerSubApp 写 window['order-utils'] → 基座校验 routes
  │        → addRoutes 注入 → 回放原始路径 → mount
  └─ 再次：沙箱 activate（已注入路由直接匹配）→ mount
离开路由 → unmount + 沙箱 deactivate
```

- 沙箱内 `window` 为 fakeWindow 代理，基座通过 `sandbox.fakeWindow[name]` 读取子应用导出，不污染真实 window；
- loader 注入 `window.__MICRO_MODULE_ENVIRONMENT__ = true` 与 `__SANDBOX_ENTRY_URL__`（异步 chunk 路径据此拦截回子应用资源目录）；
- `preload: true` 时基座在浏览器空闲期按 `priority` 升序预加载各子应用资源。

1. 子应用本地起 dev server（如 `http://localhost:9090`），确保 devServer 开 CORS；


3. 注意：本地 dev server 没有 manifest.json 时，需确认子应用入口 URL 直出可执行脚本（loader 的 `resolveEntry` 会先请求 `manifest.json`，dev 场景由子应用 webpack 配置兜底）；
4. 联调完成后恢复 UAT entry 或菜单动态下发（`getAppLoadModuleEntry('Mxxxx')`）。

## 7. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 报"未暴露 routes" | 产物分包导致 registerSubApp 未执行；或 registerSubApp 第三参误传 DOM 元素 | 关闭 splitChunks/runtimeChunk；第三参传 `null` |
| 路由跳转直接进 404 | catch-all 路由先于子应用路由注入命中 | 框架已用 `redirectedFrom` 回放处理，确认 `activeRule` 与跳转路径前缀一致 |
| 主应用 store/权限行为异常 | 子应用把 pinia 装到了宿主 app | 移除 `app.use(pinia)`，组件经 inject 使用主应用 pinia |
| 子应用图标全 404 | 注入模式未注册 svg-icon，或 publicPath 未按沙箱入口设置 | 补 `appInstance.component('svg-icon', ...)`；确认 public-path 首行执行 |
| 样式冲突/组件表现不一致 | Element Plus 版本不一致，或子应用引入了组件库样式 | 锁定同版本；`importStyle: false` |
| 本地联调加载失败 | devServer 未开 CORS，或 entry 指向错误端口 | 开 CORS；核对 entry 与 dev server 端口 |
