# 菜单角标功能接入方案（netc-pc-web-admin）

> 关联老项目：netc-pc-web（接口已接入但未做渲染，见文末"老项目现状"）

## 1. 背景与目标

服务端提供菜单角标能力（红点 / 数字 / 气泡 / 自定义图片），用于在侧边栏菜单上提示用户关注（如"新功能上线"、"N 条待办"）。老项目只完成了数据拉取，UI 层从未消费。本方案在新版基座 netc-pc-web-admin 中完整落地：**拉取 → 存储 → 渲染 → 点击消除 → 子应用联动刷新**。

## 2. 接口

| 接口 apiCode | 用途 | 入参 | 出参 |
| --- | --- | --- | --- |
| `web.user.userCornerInfo.getCornerResult` | 获取当前用户角标列表 | `{}` | `CornerItem[]` |
| `web.user.userCornerInfo.userClickEvent` | 上报角标点击（服务端消除） | `{ cornerId: number }` | - |

`CornerItem` 数据结构（对齐老项目 `MenuCorner`，netc-pc-web `src/store/modules/menus.js#L22-L30`）：

```ts
export interface CornerItem {
  /** 角标 ID（点击上报用） */
  cornerId: number
  /** 角标编码 */
  code: string
  /** 样式：1-自定义图片；2-数字微标；30-常规红点；40-气泡文案 */
  style: number
  /** 自定义样式图片链接（style=1） */
  pictureLink?: string
  /** 文案内容（style=2 显示数字，style=40 显示文案） */
  content?: string
  /** 关联的菜单 id 列表 */
  menuIdList: string[]
}
```

> 注意：老项目 `MenuItem.menuId` 为 number，新项目 `MenuItem.menuId` 为 string（`src/stores/mock.ts#L695`）。匹配时需统一为 `String(corner.menuIdList[i]) === String(menu.menuId)`，联调时与服务端确认实际类型。

## 3. 技术方案

### 3.1 API 层 — 新增 `src/apis/corner/index.ts`

复用现有 `http` 封装（apiCode 机制，`src/utils/request/request.ts#L177-L213`）：

```ts
import { http } from '@/utils/request/request'
import type { CornerItem } from './types'

/** 获取菜单角标列表（失败静默，不阻塞主流程） */
export function getCornerResult() {
  return http<CornerItem[]>('web.user.userCornerInfo.getCornerResult', {})
}

/** 上报角标点击 */
export function reportUserClickEvent(params: { cornerId: number }) {
  return http<void>('web.user.userCornerInfo.userClickEvent', params)
}
```

要求：角标接口失败**静默降级**（不打错误弹窗，仅 console.warn），不阻塞菜单加载，参考老项目 `hideErrMsg: true` 的语义。若 `http` 不支持按调用静默错误提示，需在 request 层加可选配置（如 `{ silent: true }`）。

### 3.2 状态层 — 新增 `src/stores/corner.ts`（Pinia）

独立 store，与 `lightapp` 解耦（角标生命周期和菜单列表不同：不缓存、可被子应用触发刷新）：

```ts
export const useCornerStore = defineStore('corner', () => {
  const corners = ref<CornerItem[]>([])
  const fetched = ref(false)

  /** menuId -> CornerItem[] 映射，供菜单渲染直接消费 */
  const cornerMap = computed(() => {
    const map = new Map<string, CornerItem[]>()
    corners.value.forEach((corner) => {
      ;(corner.menuIdList || []).forEach((id) => {
        const key = String(id)
        map.set(key, [...(map.get(key) || []), corner])
      })
    })
    return map
  })

  const getCornersByMenuId = (menuId: string | number) =>
    cornerMap.value.get(String(menuId)) || []

  async function fetchCorners() {
    try {
      const { data } = await getCornerResult()
      corners.value = data || []
      fetched.value = true
    } catch (e) {
      console.warn('获取角标失败', e)
    }
  }

  /** 点击菜单时上报并本地消除该菜单上的角标 */
  async function clickCorner(menuId: string | number) {
    const corner = getCornersByMenuId(menuId)[0]
    if (!corner) return
    corners.value = corners.value.filter((c) => c.cornerId !== corner.cornerId)
    try {
      await reportUserClickEvent({ cornerId: corner.cornerId })
    } catch {
      // 上报失败不回滚 UI，下次进入页面以服务端为准
    }
  }

  return { corners, fetched, fetchCorners, getCornersByMenuId, clickCorner }
})
```

要点：
- **不做 localStorage 缓存**（区别于菜单列表）：角标时效性强，每次进入基座拉一次即可；接口静默失败时角标为空，不影响菜单。
- 点击后**乐观移除**本地角标，上报失败不回滚（下次刷新以服务端为准），对齐"多层容错"偏好且实现最简。
- `fetchCorners` 幂等可重入，供子应用联动重复调用。

### 3.3 渲染层 — `src/views/admin/components/menu/index.vue`

菜单项共三处模板（一级带子菜单 L29-42、二级 L43-59、无子菜单一级 L61-69），每处 `<span class="menu-text">` 后追加角标节点：

```vue
<span v-if="hasCorner(item)" :class="cornerClass(item)" class="menu-corner">
  <img v-if="cornerStyle(item) === 1" :src="cornerPicture(item)" class="menu-corner__img" />
  <template v-else-if="cornerStyle(item) === 2">
    <span class="menu-corner__dot"></span>
    <span class="menu-corner__num">{{ cornerContent(item) }}</span>
  </template>
  <span v-else-if="cornerStyle(item) === 30" class="menu-corner__dot"></span>
  <span v-else-if="cornerStyle(item) === 40" class="menu-corner__bubble">{{ cornerContent(item) }}</span>
</span>
```

辅助方法统一取该菜单第一个角标（与老项目 `menu.corners[0]` 语义一致）：

```ts
const cornerStore = useCornerStore()
const cornerOf = (item: MenuItem) => cornerStore.getCornersByMenuId(item.menuId)[0]
const hasCorner = (item: MenuItem) => !!cornerOf(item)
const cornerStyle = (item: MenuItem) => cornerOf(item)?.style
const cornerContent = (item: MenuItem) => cornerOf(item)?.content || ''
const cornerPicture = (item: MenuItem) => cornerOf(item)?.pictureLink || ''
```

样式约定（`index.scss` 追加，兼容 `isCollapse` 折叠态）：
- `menu-corner__dot`：8px 红点，绝对定位在菜单名右上 / 折叠态定位到图标右上（复用现有 `.notice-badge` 残留样式思路，`el-reset.scss#L83`）。
- `menu-corner__num`：数字微标，超过 99 显示 `99+`。
- `menu-corner__bubble`：气泡文案（如"新"），紫底白字圆角。
- `menu-corner__img`：自定义图片，限制 max-width 28px。

### 3.4 点击消除 — `handleSelect` 接线

```ts
const handleSelect = (index: string) => {
  const menu = findMenuByIndex(index) // 按 normalizePath(menuPath) 反查 MenuItem
  if (menu) cornerStore.clickCorner(menu.menuId)
  router.push(index)
}
```

> 老项目 `menus.js` 的 `click_menu` 上报 action 从未被 dispatch（死代码），本方案在菜单选中处直接接线，避免重蹈覆辙。

### 3.5 拉取时机

1. **基座初始化**：`menu/index.vue` 的 `onMounted` 中，`lightAppStore.init()` 之后（或 `Promise.all` 并行）调用 `cornerStore.fetchCorners()`。依赖菜单就绪非强校验——角标按 menuId 匹配，菜单未就绪时渲染层自然不显示。
2. **子应用联动刷新**（二期可选）：复用 iframeBridge 通道 `src/utils/iframeBridge/constants.ts#L81-L83` 的 `ACTION_STORE_ACTION`，子应用完成某操作（如处理完待办）后通知基座重新拉角标；在 `src/stores/pc-web/storeBridge.ts#L16-L30` 的 `handleLegacyKey` 中增加对 `corner/fetchCorners` 的映射即可。
3. **不做轮询**：一期不做定时刷新，如后续有实时性要求再评估（WebSocket / 可见性轮询）。

### 3.6 Mock（开发联调）

## 5. 边界与风险

1. **menuId 类型不一致**：新老项目 number/string 混用，匹配统一 `String()` 归一，联调时与服务端确认。
2. **角标指向的菜单不存在**（下线 / 无权限）：`cornerMap` 匹配不到即自然不渲染，无需特判；但服务端应保证下发前过滤权限。
3. **折叠态展示**：折叠时一级菜单只显示图标，红点/数字需定位到图标右上角，气泡文案折叠态建议降级为红点。
4. **多角标同菜单**：一期只取第一个（对齐老项目），多角标堆叠不做。
5. **请求失败**：静默为空，菜单正常展示；不做重试（下次进入页面自然重试）。
